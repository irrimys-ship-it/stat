# Учёба — расписание, задачи, сессия

Личное приложение для учёбы: расписание с I/II неделями (вся группа ЦУТ-171 вместе, подгрупп нет; среда II недели свободна), задачи (учёба/личное), календарь, предметы
(баллы, лабы, пропуски, конспекты, файлы), сессия с вопросами, помодоро, привычки, бюджет, статистика.

- Работает в браузере на ПК и телефоне, ставится как приложение (PWA), открывается без интернета.
- Данные синхронизируются через Supabase (бесплатно, без своего сервера).
- Сайт лежит на GitHub Pages (бесплатно). Сборка не нужна — это просто файлы.

## Запуск локально

```bash
python -m http.server 5173
```

Открыть http://localhost:5173. Пока `js/config.js` пустой, приложение работает в локальном режиме.

## Подключение синхронизации (Supabase), ~10 минут

1. Зайти на https://supabase.com → Sign in (можно через GitHub) → **New project**.
   Регион — Frankfurt (eu-central-1), пароль базы придумать и сохранить себе.
2. В проекте: **SQL Editor → New query** → вставить весь файл `supabase/schema.sql` → **Run**.
   Должно быть «Success. No rows returned».
3. **Authentication → Sign In / Providers → Email**: выключить **Confirm email**
   (чтобы не ждать письмо при регистрации; аккаунт всё равно один и твой).
4. **Project Settings → API** (или **Data API / API Keys**): скопировать
   - **Project URL** (вида `https://xxxx.supabase.co`)
   - **anon / publishable key** (длинная строка)

   Вставить их в `js/config.js`. Это публичные значения, их можно класть в репозиторий.
   **service_role / secret key никуда не вставлять и никому не отправлять.**
5. Когда сайт будет на GitHub Pages: **Authentication → URL Configuration → Site URL** =
   адрес сайта (например `https://ник.github.io/ucheba/`).
6. Открыть приложение → **Настройки → Создать аккаунт** (почта + пароль). На других устройствах — **Войти**.

Бесплатный проект Supabase «засыпает», если им не пользоваться 7 дней. Тогда в панели Supabase нажать **Restore**.
Данные при этом не теряются.

## Публикация на GitHub Pages

1. На GitHub: **New repository** → имя, например `ucheba` → Public → Create (без README).
2. В этой папке:

   ```bash
   git init
   git add .
   git commit -m "Первая версия"
   git branch -M main
   git remote add origin https://github.com/НИК/ucheba.git
   git push -u origin main
   ```

   При первом `push` откроется окно входа в GitHub — войти там (пароль никому передавать не нужно).
3. В репозитории: **Settings → Pages → Build and deployment → Deploy from a branch → main / (root) → Save**.
   Через 1–2 минуты сайт будет по адресу `https://НИК.github.io/ucheba/`.
4. После любых правок: `git add . && git commit -m "…" && git push` — сайт обновится сам.

## Ссылки на папки и файлы на компьютере

- **💻 VS Code** — ссылки `vscode://file/…` открывают файл или папку в VS Code. Ничего ставить не нужно.
- **📁 Папка/файл на ПК** — открывает папку в проводнике (или выделяет файл). Один раз на каждом ПК запустить
  `tools\openpath\install.cmd` (двойной клик). Удалить — `tools\openpath\uninstall.cmd`.
- **Папки-корни** (Настройки → Папки на этом устройстве): например, корень «Учёба» = `D:\Учёба` на ПК и
  `C:\Users\…\Учёба` на ноуте. Ссылка «Учёба / СПТУ\Курсовая» тогда работает на обоих.
- На телефоне такие ссылки копируют путь в буфер.

## Быстрый ввод задач

| Пишешь | Получается |
|---|---|
| `#вмо`, `#спту`, `по ИСУТ` | предмет |
| `#личное`, `#работа` | категория |
| `сегодня`, `завтра`, `в пт`, `25.10`, `через 3 дня` | срок |
| `18:00` | время |
| `к паре` (с предметом) | срок = начало следующей пары по предмету |
| `!` / `!!` | важно / срочно |
| `лаба`, `дз`, `курсовая`, `реферат`, `тест` | тип работы |
| `каждую неделю` | повтор |

Горячие клавиши: `N` — новая задача, `/` — поиск.

## Как устроено

- `js/store.js` — хранилище: всё сохраняется в браузере и в очереди отправляется в Supabase;
  при конфликте побеждает более позднее изменение. Обновления с других устройств приходят мгновенно (Realtime).
- `js/seed.js` — начальное расписание, предметы, время пар.
- `js/model.js` — логика: недели I/II, переносы и отмены пар, «к следующей паре», разбор быстрого ввода.
- `js/views/*` — экраны.
- `supabase/schema.sql` — таблица, правила доступа (каждый видит только свои данные), хранилище файлов.
